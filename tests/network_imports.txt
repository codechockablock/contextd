# The import-level network surface of contextd/, pinned.
#
# Generated and checked by scripts/network_imports.py, which parses every
# module under contextd/ with `ast`, follows package-internal imports
# transitively (function-local imports included), and reports which modules
# can reach a socket-capable dependency. Regenerate with `--list`; explain
# with `--explain`.
#
# THIS IS NOT THE SAME GATE AS tests/network_surface.txt. That one greps for
# the words http/socket/urllib/requests and pins the files allowed to contain
# them. This one ignores spelling and follows capability. They disagree, on
# purpose, and both are kept:
#
#   * the grep sees `socket.socket(...)` typed into a fresh file, and sees
#     network vocabulary in comments and strings, which no import graph can;
#   * this sees `import psycopg` — full network reach, none of the four
#     words — and sees that `from urllib.parse import urlparse` is not network
#     reach at all, which the grep gets backwards.
#
# Lines beginning with `#` are commentary and are not compared. Every other
# line is compared exactly, in order. A NEW line means a module can reach the
# network that could not before: justify it here in the SAME commit, or remove
# the import.
#
# `=direct` means the module imports the capability itself. `=via:a+b` means it
# inherits it from a and b. A module flipping from `via:` to `direct` is a real
# change and fails the gate, even though its reach was already non-zero.
#
# ============================================================================
# HISTORY, kept because it is the point: the first pinned version of this file
# was WRONG from birth. The scanner mis-resolved `from .x import` inside
# package __init__ files (one level too high), silently dropped what it could
# not resolve, and therefore never propagated psycopg past contextd.backends —
# so ~26 of these lines were missing their psycopg reach, and the "thirteen
# modules reach nothing" claim below this comment in the old file was false
# for two of the thirteen. A merge audit caught it; the gate did not. The
# scanner now resolves __init__ imports correctly and FAILS on any internal
# import it cannot resolve, and this surface was regenerated and cross-checked
# against an independently corrected derivation (byte-identical).
#
# WHERE CAPABILITY ENTERS: three direct sites, everything else inherits.
#   ENTRY 1/3  contextd.rpc         socket=direct — the AF_UNIX client half of
#     the removed authority daemon, local IPC by construction; pinned anyway so
#     an edit to AF_INET cannot hide. (authd's own socket=direct listener was
#     deleted with the daemon, lane X.)
#   ENTRY 2/3  contextd.backends.postgres  psycopg=direct — real remote TCP, imported
#     function-locally at its use site (backends/postgres.py:370),
#     invisible to the lexical grep.
#   ENTRY 3/3  contextd.mcp_server  mcp=direct — the SDK ships HTTP/SSE
#     transports even though contextd configures stdio; flagged by package
#     name, on reputation not evidence.
# Nearly everything now shows psycopg=via:contextd.backends.postgres because
# nearly everything imports contextd.backends (often function-locally) to
# dispatch on the storage backend. That reach is REAL: any of these modules
# can open a TCP connection by constructing the Postgres backend. The modules
# that reach nothing by any path are the ones absent from the list below —
# notably contextd.canonical (the encoder every signature is computed over),
# contextd.schemas, and contextd.redact.
# pgdriver note: it is psycopg-SHAPED but psycopg-free — the capability enters
# one module over, in backends/postgres.py, at its function-local import site.
# Audits by filename or docstring put the surface in the wrong place;
# following imports puts it here.
# ============================================================================
#
# 2026-08-18, lane-t-severance: 26 lines LOST `socket=via:contextd.authd+
# contextd.rpc`. Nothing gained reach; every change here is a removal. The
# cause is one edge: contextd/db.py consulted `authd.hardened` and
# `authd.is_service_process` through a function-local import, and since nearly
# everything imports db, nearly everything inherited authd's reach into
# contextd.rpc's AF_UNIX socket. Those two predicates now live in
# contextd/authority_mode.py, which imports nothing but `threading` and the
# package config loader. The evidence core therefore has NO import-level
# network reach of any kind — socket capability is now confined to authd, rpc,
# and the four daemon front-ends that inherit from them (cli, doctor,
# mcp_server, service). The "modules that reach nothing by any path" note
# above was written when that set was three; it is now most of the core.
#
# 2026-08-18, lane-x-dissolution (C3): the authority daemon is deleted. Every
# change here is a removal or a shortened path — nothing gained reach. authd
# lost its socket=direct listener (the AuthorityService class is gone) and
# now reaches a socket only through contextd.rpc, the not-yet-deleted client
# half; cli/mcp_server/service inherit through rpc alone; doctor lost socket
# reach entirely (its daemon-deployment checks were deleted with the daemon).
